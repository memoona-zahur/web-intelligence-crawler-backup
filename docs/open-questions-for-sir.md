# Open questions for the supervisor ("sir") — crawler Phase 2

Every decision below is marked **pending sir confirmation** in the code and in the documents. Each one sits behind a setting with a safe default,
so nothing is hard-coded. If the answer is different, one setting (or one small module) changes — not the whole crawler.

| # | Question | Default used now | Why this default | Setting / where in code | What changes if sir answers differently |
|---|---|---|---|---|---|
| 1 | **Database and queue.** The requirements document recommends PostgreSQL and Redis + Celery (or BullMQ). Is **PostgreSQL with a queue stored in a PostgreSQL table** acceptable instead of Redis/Celery? | PostgreSQL 17 + Alembic migrations; the queue is the table `crawl_tasks` (leases, retries, one running task per domain). SQLite stays fully working for tests, the evaluation harness and small local runs. | RD §11-12 and MP §4 say "any durable queue acceptable". A table in the same database is transactional with the crawl data, survives restarts, needs no extra server, and runs on Windows (Redis has no native Windows build; Celery does not support Windows). Measured on this laptop: see `crawl_eval/results/scale_*` (SQLite done; PostgreSQL after install). | `DATABASE_URL` in `.env` (PostgreSQL) or unset (SQLite). Queue code: `app/crawler/queue.py` (one small module behind 8 functions). | **Redis/Celery wanted:** replace `queue.py` and `runner._drain` by Celery tasks (new dependencies `celery`, `redis`; needs Linux/WSL/Docker for Redis). The pipeline, persistence, detectors and tests stay unchanged. **SQLite only:** set no `DATABASE_URL`; works for one machine, several worker processes are possible but slower under write load; CR-H01 then passes only through its "documented and justified" clause. |
| 2 | **robots.txt answers 5xx / 429 or cannot be reached.** RFC 9309 §2.3.1.4 says treat it as "disallow" for a while. Phase 1 treated it as "allowed". | **RFC strict (disallow):** the site is not crawled now; it is retried later (after 15 min, then 30 min, then 1 h; at most 3 attempts). Status: **Blocked** when the server answered 5xx/429; **Unreachable** when the whole site cannot be reached (connection error / timeout). 4xx (401/403/404/410) = "no rules, crawl". | RFC 9309 and the project owner's decision of 2026-10-11. | `ROBOTS_5XX_POLICY=disallow\|allow` (`app/settings.py`), used in `app/crawler/fetcher.py::load_robots`. Written policy: `docs/robots-policy.md`. | `allow` restores the Phase 1 behaviour (fail-open). Five dataset rows (robots 5xx) then become MISMATCH by design. Other values of the policy (e.g. "also treat 401/403 as disallow") are a small change in `load_robots`. |
| 3 | **User-Agent contact URL.** Requirement CR-F02: a descriptive User-Agent with a real contact / policy URL. | **Required, no default.** `CRAWLER_CONTACT_URL` must be set to a real policy page or `mailto:` address; in `production` mode the crawler refuses to start without it and refuses placeholders. In `dev`/`test` mode only, the clearly marked test contact `test@example.invalid` is used, and **the crawler refuses to send it to any non-local host** (a test proves it). User-Agent: `WebsiteIntelligenceBot/2.0 (+<contact>)`. | Real sites must be able to contact the operator. A placeholder on a real site would be wrong. | `CRAWLER_CONTACT_URL`, `CRAWLER_MODE=production\|dev\|test` (`app/settings.py`; enforced for every request by `app/crawler/client.py`). | Only the value changes. The organisation (sir) should decide who owns the contact address and whether to publish a short "about our crawler" page; this is also the only sanctioned way to reduce the 11 of 21 "blocked" sites that accept another User-Agent (ISS-29): an honest, contactable crawler, never a disguise. |
| 4 | **Sites that redirect to another company's domain.** | The target is crawled and the site gets status **Redirected** (final URL stored, content kept). | Keeps the evidence and tells reviewers what happened. | `app/crawler/pipeline.py` (`redirected` flag; `same_site` in `app/domains.py`). | "Stop at the redirect" = skip the page loop when `redirected` is true and store no content. |
| 5 | **Raw HTML storage** (CR-E07 says optional, with configurable retention). | **Off.** Only cleaned text and metadata are stored. | Saves disk (several GB at 60,000 sites) and avoids storing more third-party content than needed. | `RAW_HTML_RETENTION_DAYS` (0 = off), `RAW_HTML_DIR`; purge with `python -m app.ops purge-raw`. | A positive number keeps gzip files outside the database for that many days. |
| 6 | **Contact and social signals** (CR-E12, optional) and **technology detection**. | **Deferred.** Not collected; structured data fields such as telephone are deliberately ignored. | Avoids storing personal data (CR-F08) until a policy exists. | `app/crawler/structured.py` (`name`, `description`, `address` ... only). | Needs a data-protection decision first. |
| 7 | **Per-domain request spacing and page budget.** | One request at a time per domain, at least 1 s apart (or the robots Crawl-delay up to 60 s); 8 pages per site (range 5-10); real sites run at concurrency 5. | CLAUDE.md politeness rules; MP §3A budget "about 5-10 pages". | `CRAWL_DOMAIN_MIN_INTERVAL`, `CRAWL_DELAY_MAX`, `CRAWL_MAX_PAGES`, `CRAWL_CONCURRENCY` (`app/crawler/config.py`, `app/limits.py`). | Faster crawling is possible only after a pilot shows the target sites tolerate it (CR-G08). |
| 8 | **Retry policy.** | 3 attempts per page request (1 s, 2 s back-off with jitter; Retry-After honoured up to 2 min); a site that failed for a transient reason is retried later by the queue (3 attempts per site, 15 min / 30 min / 1 h). | CR-F04, F09. | `app/crawler/config.py`, `app/crawler/queue.py` (`MAX_ATTEMPTS`, `RETRY_BASE_SECONDS`). | Any numbers can change in one place. |

Open items that need the **project owner** (not sir), before the first real-site run: the real `CRAWLER_CONTACT_URL`; confirmation that PostgreSQL 17 may be installed on this laptop.
