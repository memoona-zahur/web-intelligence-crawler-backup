Limitations of this test

  • Dataset bias: Wikidata favours large and old organisations. The 'small local business' rows are sites built with Wix / Squarespace / Shopify / Webflow / WordPress and size-filtered (≤ 80 links, ≤ 12,000 characters); they are not proven small or local.
  • Network: tested from Lahore, Pakistan. The ISP resolver fails for some names that public DNS resolves; some sites geo-block or rate-limit. Such rows are ENV-DEPENDENT, and some SITE-CHANGED rows may have the same cause.
  • One run on one day. Sites change; every row has a verification date. 100 smoke-run results were reused (same code, same dataset) so every real site was visited once; only rows that did not match were visited a second time by the probe.
  • Oracle: 19 ambiguous rows use frozen oracle_rule text; a 40-row re-probe agreed on 37/40 (40/40 with a browser for the JavaScript rows).
  • Direct-insert rows: the importer keeps only https://host, so scenario and test-endpoint rows (112) were inserted directly; the guard was relaxed only for 127.0.0.1 ports 8800–8862 and 8899.
  • Not tested: Excel upload, web paste box, 200-status challenge pages, Chromium memory, independent scaling of crawl vs AI workers, spreadsheet-formula escaping (export layer).
  • Environment note: the existing test suite created an empty data/ folder in the repo root during Step 0; the harness never opened data/websites.db.
